# Phase 0 · AI systems audit

The model is configured by the server's OPENAI_MODEL environment value. This audit did not inspect credentials, call the provider, infer the active configured model, or send project/workbook content externally. [EngineeringProvider](../../backend/orchestration/provider.py#L11) uses OpenAI Responses. Structured generation supplies a JSON schema. Research can use web search. ### Authority and failure modes

- The model selects and proposes, and the application can write model-origin assumptions to the local/hosted study as part of stage updates. CAPEX/OPEX can use them before section-specific analyst approval when enabled. This is different from a deterministic calculation accepting already reviewed user values.
- Prompts instruct the model to treat workbook data as untrusted. That instruction and valid JSON do not ensure source fidelity. Prompt injection and incorrect structured claims remain risks at model/evidence selection, even without arbitrary code/tool execution.
- Engineering approval attaches to a report. Revenue approval attaches to commercial configuration and source context. Neither is independent engineering verification of all downstream method and price assumptions. Scenario-specific authority derivation needs tested boundaries.
- Mocked provider tests can verify schema, dispatch and fallback. They cannot verify current hosted model behavior, authority in the UI, paid tool permission controls, external provider retention or source reliability.

### Phase 5 acceptance work

Use an allowlisted proposal envelope with role, prompt revision, configured model, context hash, source IDs, tool call/consent record, fallback class, candidate status and review receipt. Require canonical IDs and validators before outputs can mutate accepted study inputs. Benchmark valid but wrong JSON, fabricated citations, mismatched units, injected workbook cells, missing source values, ambiguous aliases, refusal, timeout, provider unavailable and zero external requests without consent. Track source-ID validity, deterministic handoff success, unsafe-assumption rate and abstention by task. Establish pass/fail thresholds and a human review checkpoint before any model/prompt change enters the shared pipeline.
