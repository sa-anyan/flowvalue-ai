# M3.6 · Basis of Estimate

**Date:** 12 November 2026 · **Owner:** Engineer 1 · **Gate:** G3, "Basis of Estimate complete" · **Depends on:** M3.3/M3.4 (PR #16), M3.5 (PR #18)

## What it does

`GET /api/assessments/{key}/basis-of-estimate?format=json|markdown|html` writes the Basis of Estimate from the **saved** study. It reads the saved equipment and CAPEX stage results, and runs no engine, web or AI call. The only arithmetic is one independent check that the counted breakdown categories sum to total CAPEX.

| Section | Content |
|---|---|
| Identification | Assessment, revision, source file and SHA-256, and the CAPEX run's completion time and input/output hashes |
| 1. Price basis | Currency, period, index series, and a count of equipment prices by escalation status (CEPCI, CPI proxy, none) |
| 2. Estimate class | M3.5 proposal or reviewer decision, with Table 1 accuracy range, reasons, wide-end caveats and the provisional-checklist notice |
| 3. Capital summary | Purchased equipment → total CAPEX, copied from the saved result, plus the reconciliation status |
| 4. Scope | Every priced item (model, source period, scope, amount, escalation, flags: floor, extrapolated, unverified, user comparable). Every **unpriced** item, with its reason, valued as "unknown; excluded from every total, not zero" |
| 5. Method | CAPEX method, all 17 breakdown categories with basis, provisional and AI-suggested flags, and the method's own assumptions |
| 6. Exclusions and gaps | Categories with no source, combined categories, scope gaps |
| 7. Checks | M3.4 double-count checks, pass or fail |
| 8. User assumptions | Rationale for every user edit to equipment, CAPEX, escalation or estimate class |
| 9. Sources | De-duplicated equipment-cost, capital-factor, price-index and AACE references, with file hashes or index sources |
| 10. Open items | Everything not yet resolved, generated from the above: stale result, unpriced items, gaps, failed checks, unreviewed class, CPI proxy, no escalation, unverified correlations, floored and extrapolated items, AI factors, reconciliation mismatch |

- **Stale results are labelled.** If CAPEX inputs change after the run, the report says so at the top and lists it as the first open item.
- **No CAPEX run, no report.** The endpoint returns `not_available` and says to run CAPEX.

## Charlie (local check on a copy of the saved study; nothing private recorded)

Run with the Garrett CAPEX method at minimum factors, and with feasibility deliverables assumed for the check. On the 11 November equipment results:

- 26 items priced and 2 unpriced (HE-101 and HE-102, with their reasons). Every double-count check passes, and the breakdown reconciles to total CAPEX.
- Estimate class: **4** (proposed, not reviewed).
- Open items: the two unpriced exchangers; owner's costs with no source; class not reviewed; 26 prices on the CPI proxy; 14 unverified correlations; 12 extrapolated items.

This equipment run predates the minimum-size floor (PR #14) and CEPCI (PR #16). Re-running equipment with both would leave 0 unpriced, 14 floored and 0 extrapolated. The CPI-proxy item clears once a 2025/2026 CEPCI value is added.
