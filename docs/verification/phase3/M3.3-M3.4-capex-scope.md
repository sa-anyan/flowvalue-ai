## What changed

| Area | Before | Now |
|---|---|---|
| Line with no scope | `EquipmentCost` defaulted to `purchased_equipment`, and `UnitCapitalCost` to `unit_capital` | No default. The engine and the connector reject a line with no recorded scope |
| Installed / module / unit-capital lines | Added once to plant cost with **no** factors and **no** report. | What a source already includes | `included_categories` was checked only on purchased lines and only against exact factor ids. | Breakdown | Factor lines only | `breakdown`: 17 categories, each with its amount or status, basis, source, a provisional flag and an AI-suggested flag. Categories with no registered source are explicit gaps with no amount |
| Double counting | Not checked | `double_count_checks` returns four checks with their detail |

## Scope rules as implemented

| Scope | Plant / Lang / direct factors | Indirects (engineering, construction, fee) | Contingency | Owner's costs |
|---|---|---|---|---|
| `purchased_equipment` | Yes, and only this scope | Yes | Yes | No registered factor (gap) |
| `installed_equipment` (incl. OpenPyTEA `module_estimate`) | **Never** | Only if its source **excludes** them, and only when the method states the factor on a direct-cost subtotal | Same | Gap |
| `unit_capital` | **Never** | **Never** | Only if its source excludes it | Gap |

- **Bases stay separate.** A factor on purchased equipment uses the purchased subtotal only. An eligible installed or unit line adds its own amount to a direct-cost base (Garrett `indirect_basis="direct_costs"`, Nottingham `relationships` mode fees and contingency). The per-scope base and amount are recorded on the line.
- **No basis, no charge.** Garrett's default indirect basis and Nottingham's published-table indirects are percentages of purchased equipment. Stretching them over an installed price would be a different, unpublished basis. They are therefore not applied to installed or unit lines, and each case is listed in `scope_gaps` with the reason.
- **Unknown is not excluded.** An installed or unit line whose source does not say whether it includes contingency or engineering does not receive them. The gap is reported. This avoids double counting without assuming the cost is zero.
- **Combined factors are not split.** Garrett publishes one construction-and-engineering allowance. If a source includes engineering but not construction overheads, the combined factor is not applied, and the gap is reported as `combined_factor_partly_included`.

## Acceptance fixtures (synthetic, independent arithmetic in the tests)

**Decision C fixture, Lang (fluids, 4.7).** Purchased 100, installed 300 (source excludes indirects and contingency) and unit capital 1,000 (source excludes contingency only):

| | Amount |
|---|---|
| Lang factor base | **100**, the purchased subtotal only |
| 100 × 4.7 | 470 |
| Installed, no factor | 300 |
| Unit capital, no factor | 1,000 |
| **Plant cost** | **1,770** |
| Gaps reported | Installed: engineering, construction, fee and contingency. Unit capital: contingency. Lang publishes no such factor for these scopes |

**Decision C fixture, Garrett (direct-cost basis, contingency selected at 10%).** Same three lines, all other factors at their published minimum:

| | Base | Amount |
|---|---|---|
| Purchased direct = 100 × (1 + 0.96) | — | 196 |
| Every direct factor (piping, electrical, …) | **100** | — |
| Construction/engineering 10% | 196 + 300 | 49.6 |
| Contractor fee 3% | 196 + 300 | 14.88 |
| Contingency 10% | 196 + 300 + 1,000 | 149.6 |
| **Plant cost** | | **1,710.08** = 196 + 300 + 1,000 + 49.6 + 14.88 + 149.6 |

Installation is counted once. For purchased equipment it comes from the method's direct factors. For installed and unit lines it comes from their source price. No installation-type factor reaches the installed or unit lines.

**Missing scope:** an `EquipmentCost` or `UnitCapitalCost` with no scope, or a costing line with no scope reaching the connector, is rejected and `total_capex` is `None`.

| A1 | `EquipmentCost.cost_scope` default | Any record without a scope was treated as purchased | **Fixed:** no default; rejected |
| A2 | `UnitCapitalCost.cost_scope` default | Any record without a scope was treated as unit capital | **Fixed:** no default; rejected |

## Open points for review

1. **Owner's costs** is a gap in every registered method. Following the "do not invent factors" rule, no allowance is added. A sourced owner's-cost factor (or an explicit user amount) is needed for G3.
2. **`total_capex` is not suppressed by breakdown gaps**, so existing B08 money contracts keep working. Gaps are listed in `breakdown_gaps` and `scope_gaps`. Whether a gap should make the total "partial" under decision D is for Engineer 2's B08 integration to decide.
3. **The OpenPyTEA bare-module inclusion record** uses the textbook convention and is marked provisional until its source page is checked.
4. **Excluded working capital** now shows as `excluded` with no amount in the breakdown (decision D). `CapexResult.working_capital` is still `0` for compatibility with the existing finance connector.
