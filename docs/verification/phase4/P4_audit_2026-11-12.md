# Phase 4 audit and first fixes — 12 November 2026

**Owner:** Engineer 1 · **Branch:** `e1/p4-audit` (stacked on PR #25) · **Authority:** official roadmap rev 1.1, Phase 4 (milestones M4.1–M4.6, testing, acceptance criteria, exit gate G4)

> **G4:** FlowValue can produce a complete, reproducible multi-year financial model for a supported reference project, with commercial assumptions and financial calculations fully traceable.

## Summary

Most of Phase 4 was already built before this audit:

- the six-category Revenue Box;
- Revenue Box authority and approval;
- avoided costs tied to one OPEX line;
- the cash-flow schedule;
- a financial engine with tax, debt, depreciation, working capital, NPV, IRR, MIRR, payback, break-even and levelised cost.

This audit wrote the roadmap's own Phase 4 test list as tests. It found and fixed four gaps; two remain.

**G4 is not yet passed.** No reference project has yet been run through OPEX, revenue and finance with the founder's commercial inputs, and two OPEX ledger fields are missing.

## Acceptance criteria

| Criterion | Status | Test |
|---|---|---|
| No revenue source without explicit Revenue Box authority or an approved user edit | PASS | `test_revenue_authority.py` |
| Every commercial payment is uniquely identified | PASS | `test_phase4_acceptance.py::test_duplicate_payment_identity_is_rejected`; MECE duplicate tests |
| Different payments on the same physical stream are reviewed for double counting | **PASS (new)** | `test_payments_sharing_a_stream_need_a_double_count_review`. Revenue cannot be approved until each payment records why it is distinct; an identical repeat is reported as a duplicate |
| Contracts do not extend beyond supported dates without an explicit assumption | **PASS (new)**, for lines with a term | `test_contract_expiry_2027_blocks_unsupported_2028_payment`, `test_renewal_2028_needs_an_explicit_basis_and_is_labelled`. **Limit:** a line with no `contract_term` keeps the old behaviour, where each listed year is an explicit annual assumption |
| Avoided costs cannot be both OPEX savings and independent revenue without a separate valid payment mechanism | **PASS (new review)** | `test_avoided_cost_beside_revenue_needs_an_overlap_review`; `test_six_mechanisms_are_distinct_and_avoided_cost_is_not_revenue`. The check is a required human review, not semantic detection |
| Python, financial exports and dashboard values reconcile within defined tolerances | **PASS (new)** | `test_financial_workbook.py`: relative tolerance 1e-9 in Decimal, and every workbook number read back. The dashboard and HTML report read the same saved result |

## Roadmap testing list

The roadmap asks for a wastewater integration fixture. All figures below are synthetic test inputs in the fixture's currency, not market prices.

| Roadmap test | Result |
|---|---|
| Treatment service 0.50/m³, capacity reservation 0.15/m³/year, pipeline usage 0.25/m³, environmental certificates, technology licensing and avoided treatment cost, all distinguished | PASS: five payments, each in its own category and counted once. The avoided cost is carried for OPEX and never added to revenue |
| More treated volume updates volume revenue but not the fixed capacity reservation | PASS: treatment and pipeline rise ×1.5, capacity is unchanged, and the finance ledger matches every year |
| Contract expiry in 2027, renewal in 2028 | PASS: a 2028 payment without a renewal is rejected; a renewal needs a basis and is labelled `renewal_assumed` |
| Partial-year operation | PASS: half throughput halves volume payments; contracted capacity is unchanged |
| Zero production | PASS: volume payments are zero (not unresolved), capacity is still paid, and finance runs |
| Unsold products | PASS (existing): `test_revenue.py::test_multiyear_ramp_up_and_explicit_unsold_production` |
| Conflicting billing units | PASS: rejected, with no revenue produced |
